### **Milestone 3 - Reflection**

Since **Milestone 2**, we have focused on enhancing the **DataSalaries Dashboard** based on both the professor’s feedback and the evolving needs of the project. This week, we implemented several key features and improvements to **increase interactivity**, **improve usability**, and enhance **visual clarity**.

#### **Implemented Features**

1. **Map to Show Average Salary by Location**:
   A significant addition this week is the **map visualization** displaying **average salary by location**. This feature offers an important geographical dimension to the data, which was missing previously. It allows users to understand how salaries vary across different regions. Additionally, we introduced a **location dropdown filter** in the sidebar, making it easier for users to filter the data by specific regions. This map adds valuable interactivity, enabling users to compare salaries geographically and gain insights into regional salary trends.

2. **Reorganization of Job Titles**:
   To improve the layout and user experience, we reorganized the **job titles** into **five high-level categories**. This adjustment simplifies the filtering process, reducing the complexity of the job title list and improving the dashboard’s readability. The decision to group job titles into broader categories was made to enhance **usability** and minimize visual clutter, making it easier for users to navigate and filter data efficiently.

3. **Updated Line Chart Color Scheme**:
   In response to user feedback and our focus on improving the visual clarity of the dashboard, we updated the color scheme of the **line chart** to the **'plasma' gradient** (ranging from purple to yellow). This new color scheme improves the chart’s visual appeal and makes it easier for users to interpret the data. The vibrant gradient enhances contrast, ensuring that the line chart is visually engaging while maintaining clarity.

4. **Breaking Code into Multiple Files**:
   This week, we also focused on improving the organization of our codebase by breaking it into multiple files. Previously, the code was inside one giant `app.py` file, which made it harder to manage and extend. By dividing the code into separate files, we made the project more modular and maintainable. This structure not only simplifies future updates but also improves collaboration among team members by making each component more easily understandable and editable.

#### **Changes from Proposal**

While the additions and modifications this week align well with the proposal, some adjustments were made to enhance the dashboard’s effectiveness:
- The **map chart** now provides **location-specific salary data**, which was a change from our initial, more generalized map approach. We opted for this map because it provides more **meaningful insights** and more accurately reflects geographic salary distributions.
- The **job title filter** was restructured to include fewer, more **generalized categories**, deviating from our original approach to keep the list of job titles as detailed as possible. This was done to address **layout issues** and improve user experience when interacting with the filter.

#### **Reflection on Visualization and Functionality**

The additions of the **location map** and the **updated color scheme** for the line chart have significantly improved the clarity and interactivity of the dashboard. The map adds a valuable geographic context to salary data, while the new color scheme enhances the **visual appeal** and **interpretability** of the line chart. Furthermore, the **job title categorization** has helped reduce clutter, making the filter more intuitive and user-friendly.

The **new code structure** is another major improvement. Breaking the code into modular files has made the project more organized and scalable. This will benefit us in the long term, making it easier to extend the dashboard with new features and updates while maintaining clear separation of concerns in the codebase.

The dashboard performs well in its current state, but some minor improvements could still be made. For example, **donut charts** still require further enhancements to display **proportional data** directly on the chart. Additionally, while the layout is much cleaner, future tweaks could be made to refine the filtering process for an even more streamlined experience.

#### **Looking Ahead**

In the coming weeks, we plan to:
- **Refine the map chart** and location filter to allow comparisons of salary data across different countries or broader regions.
- **Enhance visual consistency** across charts and elements by adjusting color schemes and improving layout coherence.
- Continue **performance optimization** to handle large datasets effectively, ensuring the dashboard remains fast and responsive for all users.

Overall, this week’s updates have significantly advanced the dashboard’s functionality and user experience, making it a more comprehensive and visually appealing tool for analyzing salary trends.
